# 散樱乱武 · 网页版

本程序由AI生成，由于本人是个小白，所以问题检查能力不足，请酌情游玩

把《桜降る代に決闘を》（Sakura Arms）做成**双击就能玩**的双人卡牌游戏：
纯前端、无构建、无依赖、单文件 HTML，支持热座与联机对战。

> ⚠️ **非官方同人实现**。代码用于学习与私下研究，**不包含任何官方素材**
> （卡面图 / 立绘 / 音效均不入库）。游戏规则与卡牌名称的版权属于原作者与发行方。

## 现在能玩到什么

| 项目 | 状态 |
| --- | --- |
| 女神 | **8 柱**：刀 / 薙 / 铳 / 扇 / 伞 / 书 / 毒 / 爪 |
| 卡牌 | **96 张**（88 张通常+王牌、毒袋 5 张、爪的追加札 3 张） |
| 规则 | 通常回合、攻击 / 对应嵌套、付与札、回合开始与结束阶段、再起、毒袋、风雷计略 |
| 联机 | WebRTC DataChannel + 手动邀请码，主机权威（防作弊靠状态脱敏） |
| 测试 | 11 个断言文件、2000+ 条断言、随机对局 fuzz（查卡牌守恒） |

## 怎么玩

1. 双击 **`prep.html`** —— 选女神、组卡、开房间 / 加入联机
2. 或直接双击 **`index.html`** —— 直接进战斗界面（热座双人）
3. 想直接指定牌组：`index.html?deck=01-yurina-o-n-1,01-yurina-o-n-2,...`

**不需要服务器，不需要装任何东西**（`file://` 直接跑）。

## 自备素材

仓库里**没有图**。程序只认目录结构，把素材放到与 `_work/` 同级的 `素材/` 目录：

```
素材/
├─ 卡面/<女神key>/na_<编号>_<女神>_o_<种类>_<序号>.png
├─ Sprite/         头像、动作图标、UI 图
└─ AudioClip/      音效与 BGM
```

- `卡面/` 缺图时，卡牌位置显示占位框，**规则逻辑不受影响**
- `Sprite/` 缺图时，头像与图标退化为文字
- `AudioClip/` 缺文件时静默跳过

## 目录结构

```
散樱乱武/
├─ index.html             战斗界面（Canvas 绘制，唯一在用的 UI）
├─ prep.html              主界面：选人 / 组卡 / 联机入口
├─ _work/
│  ├─ assets.js           卡面路径清单（脚本生成，勿手改）
│  └─ gamedata.js         卡牌数据（脚本生成，勿手改）
├─ data/cards.json        96 张卡的源数据（改这里，再重新生成）
├─ game/
│  ├─ engine/             rng / state / rules / effects / actions / gauge / plan / umbrella
│  └─ tests/              断言测试（run_all.js 跑全部）
├─ net/                   WebRTC、协议、状态脱敏、会话
├─ docs/                  规则、机制、UI、卡牌效果接口
├─ 讨论记录.md            每个阶段做了什么、为什么（含踩坑）
└─ HANDOFF.md             交接说明
```

引擎是 UMD 风格，浏览器 `<script>` 与 Node `require` 共用同一份代码。
**状态必须是纯 JSON**（不含函数、类），这样可以克隆、存档、联机同步。

## 开发

```bash
# 跑全部断言
node game/tests/run_all.js

# 单个文件
node game/tests/spec_chikage.js

# 语法检查
node --check game/engine/rules.js
```

改卡牌数据的流程：

1. 改 `data/cards.json`
2. 跑生成脚本，重新产出 `_work/gamedata.js` / `_work/assets.js`
3. 跑测试，并**看一眼截图**（只看文件大小不算数）

## 已知限制

- 没有 AI 对手，只有热座与联机
- 联机没有中转服务器，需要双方能直连（NAT 打洞失败的场景未处理）
- 素材不在仓库里，第一次运行是"无图可玩"的状态
