## 1. APK 构成

- 445 MB，2626 个条目，确实是标准 APK（ZIP）
- **Unity IL2CPP**：`lib/arm64-v8a/libil2cpp.so`（61 MB）、`global-metadata.dat`（10 MB）
- **另外还有 xLua**：`libxlua.so` —— 说明部分逻辑可能用 Lua 写（脚本位置尚未找到）
- `assets/bin/Data/` 下全是 **哈希命名的分片**（`8f3a...assets.split12` 之类），AssetStudio 才能正确读
- 三个**明文数据文件**，这才是重点：

| 文件 | 大小 | 内容 |
| --- | --- | --- |
| `assets/data_2_0_9.db` | 987 KB | **SQLite 数据库 ← 核心，卡牌数据全在这** |
| `assets/decksquare/deck2022.txt` | 241 KB | 玩家分享的**卡组列表**（UTF-16 LE，Tab 分隔，370 行） |
| `assets/decksquare/decksquare.csv` | 162 KB | 同一批卡组的 CSV 版（**GB18030 编码**，不是 UTF-8） |

> 顺带一提：`deck2022.txt` 里的 `decklink` 指向 `sdrice.name` 的组卡器，`season` 到 `S7` —— 可以看出这是一个**跟到 S7 赛季的民间汉化/对战平台版本**。

## 2. 数据库结构

`data_2_0_9.db` 共 4 张有效表：

| 表 | 行数 | 用途 |
| --- | --- | --- |
| `cards` | **676** | 全部卡牌 |
| `characters` | 60 | 25 位女神 + 异格版本 + 剧情角色 + 东方联动 |
| `skin` | 27 | 卡号 → 立绘皮肤代号（如 `a1`） |
| `story` | 21 | 剧情关卡的标题与脚本引用 |

### 2.1 `cards` 字段

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `id` | int | 主键 | |
| `card_number` | text | **卡牌唯一编号** | 命名规则见 §3 |
| `card_name` | text | 卡名 | 中文为主 |
| `user_info` | text | 制作者 | 多为女神脚本名，如 `yurina` |
| `card_type` | int | 牌种类 | 0=通常, 1=王牌, 5/6/7/8/9=特殊（见 §4） |
| `main_type` | int | 大类别 | 1=攻击, 2=付与, 3=其他, 0=缘, 4=特殊 |
| `sub_type` | int | 副类别 | 0=通常, 1=对应, 2=全力 |
| `damage_aura` | text | **对「气」的伤害** | 空=无，`X`=可变 |
| `damage_life` | text | **对「命」的伤害** | 同上 |
| `range` | text | **攻击距离**（间合） | 逗号分隔，如 `3,4,5`；空=非攻击 |
| `cost` | text | 费用 | 支付气场/结晶，`X`=可变 |
| `charge` | text | 充填数 | 该牌展开时放置的樱花结晶数（推断） |
| `card_text` | text | **效果文本** | 核心资产，含 `【常时】/【攻击后】/【展开中】/【破弃时】` 等时点标记 |
| `embedding` | text | 向量（339 维） | 用于卡组相似度推荐，**做游戏时没用，忽略** |

### 2.2 `characters` 字段

`charaId`（如 `02_saine_o`）、`charaName`（细音）、`script`（`saine`）、`keyword`（该女神的特殊规则，例：细音是「当你的%自装%为1或以下时，一部分卡牌将会强化」）、`enable`、`relative`。

> ⚠️ `keyword` 里的 `%自装%`、`%自命%` 是**占位符**，对应游戏内的「自装/自命/敌装/敌命」；`description` 字段基本是空的，**没有女神简介文本**。

## 3. 卡牌编号规则（已破译）

```
na_01_yurina_o_n_4          ← 常规
na_01_yurina_o_n_4_s2       ← 同一张卡的另一印版（版本修订/旧版）
na_02_saine_o_s_3           ← 王牌
na_00_hajimari_a_n_1        ← 00 = 共通基础牌池（始）
story_02_a_4                ← 剧情专用牌
th_06_youmu_o_n_1           ← 东方联动
```

| 段 | 含义 | 取值 |
| --- | --- | --- |
| 1 | 时点 | `na`=主卡池（627 张）、`story`=剧情、`th`=联动 |
| 2 | 角色号 | `01`~`25`，`00`=共通 |
| 3 | 角色脚本名 | `yurina` / `saine` / ... |
| 4 | 角色版本 | `o`=原版，`a1`/`a2`=异格 |
| 5 | 牌种 | **`n`=通常牌，`s`=王牌** |
| 6 | 序号 | 该角色内的序号 |
| 7 | 印版 | 可选，`_s2` 表示同卡的另一版本 |

> **重要**：同一张卡（如摇波的「居合」）在库里有两行：`na_01_yurina_o_n_4` 和 `na_01_yurina_o_n_4_s2`，数值略有差异（距离 `3,4` vs `2,3,4`）。**做牌池时要去重并选一版**，选哪版待定。

## 6. 数据质量与已知的坑

1. **重复印版**：676 行里约有若干是 `_s2` 变体，真正卡数少于 676（待精确统计）。
2. **7 张日文未翻译**（见上），其余为中文。
3. **数值有 `X`**：伤害/费用可以是变量，不能当整数存，规则引擎需要「表达式」而非「数字」。
4. **文本格式不统一**：`【常时】/【攻击后】/【攻击后】`、`/ ---- /` 分隔符、`●` 列表符混用 —— 解析器要能容忍。
5. **`发动`/`埋め` 等错别字**：库里存在「破弃时」「破棄時」繁简混用，也有明显笔误。**规则引擎不能靠字符串匹配**，得靠结构化字段 + 手写实现。
6. **没有规则书**：`气 / 命 / 装 / 距离 / 集中力 / 樱结 / 決死 / 八相 / 连火 / 境地` 这些机制的**准确流程**，只能靠效果文字反推 + 我的规则知识，**必须逐条和你核对**。
