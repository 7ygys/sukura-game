# 散樱乱武 · 开发守则

单文件 HTML 游戏，双击即玩（`file://`），无服务器、无构建、无依赖。

## 一、铁律（违反过，都出过事故）

1. **先查规则原文，再写代码。** 官方总合规则：`furuyoni.sekiseiro.com/re/rules/comprehensive-rule/core/`。
   用户给的描述与规则书冲突时**以用户为准**（他对着实际游戏在玩），但要把两者都写进 `讨论记录.md`。
2. **改动直接改原文件**（`_work/scene_v17.html`），不要每次新建一个 v18/v19。
3. **删除 / 不可逆操作前，先列名单，等确认。** 包括 `git reset`、批量删文件、覆盖他人素材。
4. **不要请求提权**，也不要 `git push` 到未知远端。
5. **改完必须真的看截图。** 「文件 1600KB」不等于画面对——曾经交出去一张只有背景视频的白屏。
6. **每改一个机制，顺手加断言**，并在 `讨论记录.md` 追加一节（阶段 N）。
7. 用户是初学者：代码多写中文注释，解释「为什么」，不只写「是什么」。

## 二、项目结构

```
散樱乱武/
├─ _work/scene_v17.html     战斗界面（Canvas，唯一在用的 UI）
├─ _work/prep.html          主界面 / 选人 / 组卡
├─ _work/assets.js          卡面路径清单（脚本生成，勿手改）
├─ _work/gamedata.js        卡牌数据（脚本生成，勿手改）
├─ data/cards.json          44 张卡的源数据（手改这里，再重新生成）
├─ game/engine/*.js         rng / state / rules / effects / actions
├─ game/tests/run.js        断言测试
├─ docs/                    规则、UI 现状、卡牌效果接口
└─ 讨论记录.md              每个阶段做了什么、为什么
```

引擎是 UMD 风格，浏览器 `<script>` 和 Node `require` 共用同一份代码。
**状态必须是纯 JSON**（无函数、无类），便于克隆、存档、将来联机。

## 四、踩过的坑（症状 → 原因 → 正确做法）

### 4.1 JS 语言层面的坑

| 症状 | 原因 | 正确做法 |
| --- | --- | --- |
| 伤害是 `2/0`，选修命却扣了 1 点 | `Math.min(x, n \|\| 1)`：**0 是 falsy**，`0 \|\| 1 === 1` | 显式判 `n === undefined \|\| n === null ? 1 : n` |
| 整页白屏，只剩背景视频 | `arr[arr.length-1].x` 在**空数组**上抛异常，而 `requestAnimationFrame` 在函数最后一行 → 循环直接死 | 取末项前判空；**帧循环包 try/catch 并重新排下一帧** |
| 某个音效/动画偶尔不播、偶尔重播 | 事件数组有 50 条上限会 `shift()`，界面却按**下标**记进度 → 整体错位 | 事件带只增不减的 `seq`，界面只处理 `seq > lastSeq` |
| 免费基本动作却要求付集中力 | `basicAction` 改成 opts 对象后，调用方还在传布尔 `action.free` | 统一传 `{free, pay, cardId}` |
| `card is not defined` | 把新代码插到 `basicAction` 里（锚点文本在多个函数里都出现） | 用 `edit` 配**唯一**锚点；插完 `--check` |
| 测试里 `ok` 不是函数 | 局部变量 `const ok = ...` 遮蔽了断言helper `ok()` | 换名 `did` |
| Python 脚本报路径不存在 | 中文路径 + argv/内联字符串编码 | 脚本写到 `%TEMP%` 的 ASCII 路径，或 `UTF8Encoding($false)` 写入 + `r"..."` |

### 4.2 引擎逻辑的坑

| 症状 | 原因 | 正确做法 |
| --- | --- | --- |
| 重组后牌凭空消失 | `p.deck = shuffle(back)` **覆盖**了牌库剩余牌 | `shuffle(p.deck.concat(back))` |
| 八方振り / 石突き 的第二击不见了 | `resolveDamage` 末尾无条件 `pending = null`，把【攻击后】刚生成的攻击冲掉 | 只有 `state.pending === pd` 时才清空 |
| 【攻击后】完全不触发 | `generateAttack` 生成时 `cardId: null`，效果表查不到 | 生成攻击时记住 `spec.cardId` |
| 石突き 的【攻击后】打两次 | `respond` 里调了一次，`resolveDamage` 里又调一次 | 只留 `respond` 里那次（词条印在谁身上就归谁结算） |
| 没打牌却弹出「是否对应」 | 上一次攻击留下了没人处理的 `pending`（多半是上一条的重复触发） | 修重复触发；并给 `pending` 加断言测试 |
| 结晶飞错方向（宿命画成命→气） | 界面靠「哪个数字变了」**猜**移动 | 所有移动走 `moveCrystal()` 并 emit `move` 事件，界面照事件播 |
| 付与札取结晶时动画错乱 | 付与札不是数值区域 | `moveCrystal` 里把 `'attach'` 当**伪区域**：不动数值，只发事件 |
| 【对应】顺序不对 | 对应是**嵌套解决**（规则 9-4-ⅰ） | `state.attackStack`：对应牌生成攻击时把原攻击压栈，打完再弹回 |
| 「-」被当成 0 | `gamedata` 生成时 `life: null` → `0` | 全程保留 `null`；引擎拒绝选「-」那条 |
| 全力卡还能配王牌 | 只挡了通常札 | 用过《全力》后 `playCard` / `basicAction` **全挡**，只能结束回合 |
| 見切り 不能当对应 | 数据里没有 `reaction` 类型 | 效果表加 `canRespond(state, who)`，条件满足即可当对应 |
| 圏域 在间合满时把结晶丢进虚 | 只判断了 `distance < 10` 否则进虚 | 无处可去时**留在牌上**（规则 10-42） |
| 对应后距离变了却照常命中 | 缺「适正距离再确认」 | `recheckRange()`：respond 之后、choice 之后都要查 |

### 4.3 UI / 交互的坑

| 症状 | 原因 | 正确做法 |
| --- | --- | --- |
| 畏缩图标看不见 | 画在 `strip.x + strip.w + 8`，布局左右对调后出屏 | 画在状态栏**左侧** |
| 付与结晶飞行动画看不见 | 回合开始的弹窗遮罩盖住了 | `turnStart` 事件 → 扫黑条 + **1.25s 弹窗冻结期** |
| 黑条和弹窗同时出现 | `act()` 里先 `syncPending()` 后 `pumpEvents()` | 反过来：先 `pumpEvents()`（设冻结期）再 `syncPending()`；冻结期结束那帧补一次 |
| 音效完全没声 | `loadSfx()` 写好了但**从没被调用** | 初始化处必须调用；`playSfx` 空对象就静默 return，很难发现 |
| 盖牌/出牌误触点击音 | 拖拽松手后浏览器会补一个 `click` | `S.swallowClick` 吞掉那一次 |
| 卡面图片 404 → 只剩占位框 | 素材换了文件名（`na_..._s6_2.png`） | 改素材后**重新跑扫描脚本**生成 `assets.js` |
| `?stagger=1` 没效果 | 调试参数写的是旧的 `S.staggered`，界面读的是 `G.players[].staggered` | 调试参数要跟着状态源改 |

## 五、核心机制检查清单

改任何一条时，逐项对着官方规则核一遍：

**回合**
- [ ] 开始阶段：付与札各掉 1 颗结晶进虚；付与破弃时触发【破弃时】
- [ ] 抽 2 张；牌库不够 → **焦燥**（1 张缺 1 点，玩家自己选装/命）
- [ ] 重组询问：**每回合可选，扣 1 点命，只洗通常札**（弃牌区 + 盖牌区）
- [ ] 结束阶段：手牌 > 2 → **盖成伏札**（不是丢进弃牌区）
- [ ] 再起在**结束阶段**检查；即再起**随时**检查

**基本动作**（每个 1 集中力 **或** 1 张手牌盖成伏札）
- [ ] 前进：间合 > 达人距离，且装未满
- [ ] 后退：装 ≥ 1
- [ ] 缠绕：虚 ≥ 1 且装未满
- [ ] 宿命：装 ≥ 1
- [ ] 离脱：间合 ≤ 达人距离 且 虚 ≥ 1

**攻击**
- [ ] 适正距离用 `effDistance()`（= 结晶数 + 临时修正）
- [ ] 气伤上限 5（超克解除）；命伤 → 气，装伤 → 虚
- [ ] 对应可从手牌**或**未使用王牌；王牌要付气
- [ ] 对应后**重新确认适正距离**
- [ ] 伤害 `-` 与 `0` 语义不同：`-` 不能选，`0` 可选但不扣

**三个距离概念（极易混淆）**
| 概念 | 作用 |
| --- | --- |
| 间合 | 轨道上的结晶数，就是当前距离 |
| 达人距离 | 只决定「前进 / 离脱」能否做（默认 2，圏域 +1） |
| 适正距离 | 印在攻击牌上的 3-4 / 4-5，决定能不能打到 |

## 七、提交规范

```
git add -A
git commit -m '一句话说清改了什么'
```

- 仓库只放**代码和文档**：素材、音频、视频、生成物一律 `.gitignore`
- `.gitignore` 里要放行 `_work/` 下的两个 HTML 时，必须写
  ```gitignore
  _work/*                      ← 排除内容（不是 _work/，整个目录被排除后文件捞不回来）
  !_work/scene_v17.html
  !_work/prep.html
  ```
- 每一次提交都同步在 `讨论记录.md` 追加「阶段 N」，写清**原因**而不只是结果
